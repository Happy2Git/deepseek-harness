# Agent Note: 拖文件文本录入与整批边界

Status: implemented

[English](2026-08-15-drag-file-text-intake.md) | 中文

## 问题

浏览器拖拽暴露的是文件*内容*而非路径——OS 拖入的文件要交给模型就必须在浏览器里读取，但把大体积内容停进输入框（或直接粘进草稿）会撑爆编辑器并卡死文本区。该特性需要有界读取、只在提交时折入消息的芯片，并满足仓库「模型可见 ⟺ 已记录」的不变量。

## 决策

**整页拖放录入 + 停放芯片。** 编辑器注册 document 级拖放监听（编辑器槽是 `kind: 'single'`，最多一个栏绑定它们）；文本文件（非图片 MIME）在浏览器内读取并停放为芯片（`PendingTextFile { name, content, size }`）。提交前草稿保持为空：提交时 `foldPendingFiles` 把围栏块（` ```name\ncontent\n``` `）追加进草稿并清空芯片。

**任何读取之前、对整批执行边界检查。** 单文件 ≤ 256 KiB（`MAX_TEXT_FILE_BYTES`）、总量 ≤ 1 MiB（`MAX_TEXT_FILES_TOTAL_BYTES`）、数量 ≤ 20（`MAX_TEXT_FILES`）；NUL 字节判定二进制并丢弃该文件。超限批次整批拒绝并以产品文案提示（toast），不添加任何内容。预检读取一个 ref（`pendingFilesRef`），它在异步读取*之前*同步预留每个已接受批次的字节数与数量——快速第二次 drop 的预检若落在第一批还在读取时，必须把第一批计入，否则两次 drop 都可能通过并突破上限；不可读批次回滚其预留。`removePendingFile` 与 `foldPendingFiles` 同步维护 ref 与状态（无 effect 同步）。

**模型可见 ⟺ 已记录。** 芯片只在提交时成为模型输入：折入时写入 `session.prompt`，作为普通的持久化 `user/message` ——与手打文本同一条路径，回放可以重建它们。

## 备选方案

**拖入即粘贴进草稿。** 否决：256 KiB 内容在文本区里无法编辑，且拖入活草稿让「撤销这次拖入」变成一次巨型文本变更。

**提交时才惰性读取。** 否决：文件快照必须在 OS 拖拽还保证内容时读取；晚读可能错过变更或消失（拖拽暴露的是内容不是路径）。

**边界只对状态检查。** 否决：状态晚一个渲染才更新；同一 tick 内两次 drop 会双双通过预检（ref 同步预留正是修复手段）。

## 后果

拖入的文本文件在记录与回放上等同于手打输入，但提交前不给编辑器任何成本。拒绝是整批的：突破任何边界的拖入不产生部分芯片。录入读取的是 OS 已经暴露给页面的文件内容——没有新的信任面，边界就是完整结果包络。

## 测试

`packages/client/ui-conversation/tests/input-bar.client.spec.tsx` 覆盖芯片停放与提交折入、二进制拒绝、单文件/整批/总字节/总数拒绝及产品文案、快速二次 drop 竞态（第二批被第一批的预留拒绝）、投影限制的浮层文案。
